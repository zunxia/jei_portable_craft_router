# 1.3.5 发布说明

修复通过 JEI“编写样板”打开无线通用终端后，使用左侧按钮切换到合成终端导致菜单打开失败并断开世界的问题。

服务端重新发送菜单定位器时，改为读取原槽位真实物品的最新组件，确保客户端创建的宿主与当前终端模式一致。覆盖背包与 Curios 的通用终端；保留物品校验、真实扣电和既有网络格式。

详细原因和验证结果见 [VALIDATION-P10.md](VALIDATION-P10.md)。安装时将旧版路由 JAR 替换为 `jei_portable_craft_router-1.3.5.jar`，客户端与专用服务端均更新后重启；单人只需更新客户端。

构建成品大小：85,204 字节。SHA-256：`CEF37FB2D95DFCDA62F035ECDFBF6FB83D2FC9F1134B09B59829AF9238597A13`。

NeoForge 21.1.251 / JEI 19.57.0.446 的 55 个隔离场景全部通过；NeoForge 21.1.249 / JEI 19.50.0.414 的背包、Curios 连续切换场景通过。旧版已复现同一故障。83 个 JEI 构件及 32 套依赖组合的接口检查通过。

## 已知问题与验证边界

局域网联机仍有通用终端切换合成、样板访问模式后菜单宿主不匹配的反馈。反馈日志确认加入者客户端为 1.3.5，但无法确认房主的实际构件及完整触发条件，尚不能判定为两端版本差异或其他同步缺陷。房主和加入者均需更新；遇到问题请提供双方同一时间的日志。现有隔离回归不等同于局域网或所有终端模式的完整验证。

跨终端操作仍包含等待菜单同步及约 5 个客户端 tick 的固定缓冲。本次发布未修改该等待机制。
