# 1.3.4 JEI .392 与更早接口兼容验收

日期：2026-10-09。目标：检查 ATM10 7.3 的 JEI `19.43.0.392` 前后接口，扩大兼容范围，取消按 JEI 版本号禁用功能。

## 结论与改动

JEI `19.43.0.390–398` 的已发布构件，以及 `19.44.0.399–413` 的已发布构件，均匹配原有旧控制器和旧布局；`.392` 的失效直接来自 1.3.3 的白名单。1.3.4 删除 `JeiVersionSupport` 和客户端、mixin 中的版本判断。客户端在 JEI 已安装时启用，控制器和布局分别核对实际字段、方法并选择相应注入，转移服务按类是否存在选择。

进一步下载作者 Maven 的全部 248 个 1.21.1 NeoForge JEI 构件，发现更早版本还有两处直接调用不兼容。修复后，`19.27.0.335–19.57.0.451` 范围内全部 83 个已发布构件通过接口审计。

| 接口变化边界 | 发现 | 处理 |
|---|---|---|
| 19.25.1.334 → 19.27.0.335 | 旧 `RecipeTransferButton` / `GuiIconToggleButton` 改为 `RecipeTransferButtonController` / `IconButton`，加入按钮列表与工厂 | .335 起匹配当前适配器；更早架构未实现 |
| 19.28.0.351 → 19.32.0.358 | `IConnectionToServer` 增加 `canSendPacket` | 改用 NeoForge 客户端连接的 `hasChannel`；仍先要求 `isJeiOnServer` |
| 19.42.0.389 → 19.43.0.390 | `Internal` 增加 `getOptionalJeiRuntime` | 统一调用各版本都有的 `getJeiRuntime`，尚未初始化时返回空结果 |
| 19.43.0.391 → .392 → .393 | 本路由所用类型、成员和注入签名没有差异 | 取消版本号白名单后使用旧适配器 |
| 19.51.0.420 → 19.52.0.421/.422 | 旧控制器配新布局、转移服务和结果包 | 分别按实际结构选择控制器、布局及转移实现 |
| 19.52.0.422 → .423 | 控制器改为服务和 supplier 字段 | 使用新控制器适配器 |

上述边界按已发布 NeoForge 构件描述，中间缺号不表示存在对应版本。审计针对本路由实际使用的接口，不声称 JEI 的所有接口都未改变。

## 复现

将 Java 21 的 bin 加入 PATH 后：

```powershell
./build.ps1 -NeoForgeVersion 21.1.249
./scripts/check.ps1
./scripts/check-jei-matrix.ps1 -Download
./scripts/build-probe.ps1
./scripts/smoke-client.ps1 -WithProbe -Session atm73-check -InstanceDir 'E:\BaiduNetdiskDownload\PCL 正式版 2.13.0.1\.minecraft\versions\ATM10 7.3' -NeoForgeVersion 21.1.247
./scripts/version-smoke.ps1
```

已下载构件后去掉 `-Download` 可离线复查。矩阵默认只检查上述 83 个构件；全量探索可指定 `-MinVersion 19.8.4.110 -ExpectedCount 248`，会报告 165 个旧架构构件未匹配的预期失败。

## 验证范围

没有 JEI 版本保护。接口缺失时无法使用现有注入；实际调用异常仍终止路由并记录错误。服务端 JEI 及通道握手、物品合法性与电量/链接校验均保留。

27 个较早的已核对 JEI 构件声明 NeoForge `[21.0.118-beta,)`，19.42.0.379 起的 56 个构件声明 `[21.1.238,)`。实际安装还需满足本路由与所有终端依赖的要求。

静态审计不等同于逐个版本的游戏回归。此次没有重跑专用服务端双客户端和完整整合包冲突矩阵。Skyhive 中 AE2 Lightning 2.1.1 与 Polymorph 1.1.0 的旧 JEI 注入冲突仍是独立问题。
