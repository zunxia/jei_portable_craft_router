# 1.3.3 JEI 19.50–19.57 兼容验收

日期：2026-10-09。目标为 Minecraft 1.21.1 NeoForge JEI `19.50.0.414` 至 `19.57.0.451`，包含 Skyhive 的 `19.57.0.449`。

## 原因与实现

1.3.2 的 JEI 白名单仅有 `.414` 和 `.446`，因此 `.449` 会正常加载模组但禁用路由。此次为范围内全部 30 个已发布的 NeoForge 构件加入白名单，并逐个核对实际二进制，继续拒绝范围外和未发布的版本。

JEI 的布局和控制器并非同时升级。旧实现使用一个标志选择全部 mixin，会对 `.421/.422` 选择错误的布局。1.3.3 分别选择控制器与布局；转移兼容层继续调用各 JEI 版本自身的实现和网络包。

| JEI 版本 | 控制器 | 布局 | 转移接口 |
|---|---|---|---|
| 19.50.0.414；19.51.0.416–420 | 旧 | 旧 | RecipeTransferUtil / PacketRecipeTransfer |
| 19.52.0.421、422 | 旧 | 新 | RecipeTransferService / PacketRecipeTransferWithResult |
| 19.52.0.423 至 19.57.0.451 的已发布版本 | 新 | 新 | RecipeTransferService / PacketRecipeTransferWithResult |

`JeiMatrixChecks` 从编译后的路由类提取 37 个 JEI 类型、50 个成员引用，核对各构件中的描述符、公开可见性、静态属性和继承成员。另检查反射使用的转移方法、服务构造函数、包通道及两种 mixin 签名的匹配/排除。全部 30 个构件通过；空版本、非法版本、未发布版本 `.415`、未来版本 `.452` 等继续拒绝。

所有 30 个 JEI 构件的 NeoForge 最低依赖声明均为 `21.1.238`。本模组仍声明 `[21.1.169,21.2)`，实际运行必须同时满足 JEI 和其他模组的依赖。

未知版本启动保护：仅修改隔离副本的 JEI 元数据为 `19.58.0.0`，客户端正常启动并进入世界，mixin 与客户端路由均禁用，探针确认原始「配方太大」按钮仍禁用后正常退出。该测试验证保护行为，不代表支持未来版本的真实二进制。

## 复现

本机将 Java 21 的 `bin` 加入 PATH 后运行：

```powershell
./build.ps1 -NeoForgeVersion 21.1.249
./scripts/check.ps1
./scripts/check-jei-matrix.ps1 -Download
./scripts/build-probe.ps1
./scripts/smoke-client.ps1 -WithProbe -Session jei421-check -JeiJar build/jei-matrix/jei-1.21.1-neoforge-19.52.0.421.jar
```

`-Download` 仅首次获取构件需要，后续矩阵检查可以离线运行。`-JeiJar` 只替换隔离客户端的 JEI。完整原始日志保存在本机忽略目录 `docs/validation/p7-*`。

## 限制

二进制检查覆盖全部 30 个版本，完整运行回归仅覆盖上表列出的版本；不将静态检查等同于每个版本的完整游戏验收。本轮未重新运行专用服务端双客户端矩阵。

Skyhive 原日志还存在 AE2 Lightning `ae2lt-2.1.1.jar` 对旧 `recipesGui` 字段的注入、Polymorph `1.1.0` 对旧 `RecipeTransferUtil.transferRecipe` 的注入失败。这些是其他模组的 JEI 兼容问题，本次仅修复本路由模组。使用 Skyhive 核心依赖通过，不代表所有模组同时加载的完整包已无冲突。

本次未修改正式实例的模组、存档或 JEI，也未重启正式游戏/服务器。原始规划文档保持不变。
